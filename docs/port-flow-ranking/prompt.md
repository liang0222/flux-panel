## 功能需求

**R1 采集与持久化**：每 5 分钟采集一次各端口转发的流量数据并写入数据库；服务重启后历史记录仍可查询。

**R2 统计单元**：以端口转发规则（`forward`）为单位统计——这是项目现有计数器（`forward.in_flow/out_flow`）的粒度，gost 服务名也按转发生成。排行展示其入口端口（`forward_port.port`）；一条转发有多个入口端口时展示全部端口，流量不拆分。

**R3 增量计算**：优先使用现有计数器，通过**相邻两次采集值的差额**计算新增流量；正确处理计数器重置、端口/转发删除、采集数据缺失；不得产生负值或重复累计。

**R4 统计范围**：提供「今天」「近 3 天」「近 7 天」「近 30 天」四种；「今天」按项目现有时区规则（JVM `-Duser.timezone=Asia/Shanghai`）从当日零点起算；其余按最近对应天数统计；接口返回实际区间文本供页面展示。

**R5 排行展示**：每个范围内按端口累计转发流量**降序**排列，展示端口标识与对应流量；明确总流量包含的方向，并遵循项目现有流量统计口径。

**R6 历史保留**：至少保留 30 天；统计范围切换后展示相应周期的排行榜。

**R7 集成**：接入现有管理界面与必要的数据接口，保持与 v2.0.7-beta 的依赖和运行环境兼容。

## 已确认口径（以此为准）

1. 总流量 = **入站 + 出站**；两者取自 `forward.in_flow` / `forward.out_flow`，已在上报时按 `tunnel.traffic_ratio`（倍率）与 `tunnel.flow`（单向/双向计费）换算，排行**不得二次换算**。
2. 「今天」= 项目时区当日 00:00 至请求时刻；「近 N 天」= **含今天在内的最近 N 个自然日**（近 3 天 = 今天 + 前 2 天），区间归属以采集点时间为准（5 分钟粒度）。
3. 首次采集**只建立基线**（增量 0），不把启用功能前的历史累计计入任何区间。
4. 仅在「首次基线」或「有新增流量」时落库；采集任务本身仍每 5 分钟执行一次。
5. 保留 **31 天**（满足 ≥30 天），每日低峰清理过期采集记录。
6. 接口**仅管理员可用**（`@RequireRole`），菜单项 `adminOnly`；非法 `range` 返回错误，缺省为 `today`。
7. 统计行必须冗余名称/端口/隧道/用户快照，转发被删除后历史仍可展示（标记「已删除」）。

## 非功能与约束

- 不新增第三方依赖、不改现有依赖版本、不改 Docker/启动脚本、不改 `application.yml` 的运行必需项；如果需要新增表，必须通过项目既有的 `schema.sql` + `spring.sql.init.mode=always` 幂等建表，**无需手工迁移**。
- 采集任务必须异常自愈（try/catch 记日志），不得因单次失败中断调度。
- 存储规模要可控：给出估算，避免「每端口每 5 分钟无条件写一行」这种在 30 天保留期下会膨胀到百万行的设计。
- 沿用项目代码风格：中文注释、`R.ok/R.err`、`@LogAnnotation`、Service/Mapper 分层、前端 HeroUI + 暗色类名。

## 测试要求（必须新增，且能 `mvn test` 直接跑）

1. **异常计数器**：首次采集、正常差额、双向回退、单方向回退、采集缺失后恢复、null/负数、不产生负值。
2. **区间聚合**：今天从当日零点起算、3/7/30 天的起点、跨月边界、非法范围解析。
3. **排序与展示**：总流量降序、并列时按转发 ID 升序、rank 连续、总流量/端口数/转发数汇总正确、基线 0 行不进入排行、已删除转发使用快照。
4. **采集落库**：写入内容（快照/增量/重置标记/累计值）、无增量跳过、无端口记录、无可采集转发。
5. **接口契约**：管理员 200、非管理员 403、未登录 401、非法 range 报错、缺省 today、（建议）真实 SQLite 上验证建表与聚合 SQL、重启后仍可查。

## 追加需求（2026-10-21 确认）：仪表盘实时速率

**R8 位置**：集成在仪表盘（4 张统计卡下方），不单独开页。

**R9 数据来源与口径**：使用节点每 5 秒上报的服务增量（`/flow/upload` 的 `d/u`，已按倍率与计费换算），在内存中做 **10 秒滑动窗口**（上报间隔的 2 倍）换算速率；**不落库**，服务重启后从零累积。总速率 = 入站 + 出站。

**R10 展示内容**：总速率（自动 Kbit/s → Mbit/s → Gbit/s）、入站/出站速率与占比条、有流量的端口数与用户数、最忙端口（名称:端口）、最高用户、最近上报时间；每 2 秒刷新，页面隐藏时暂停，失败保留上一次数值。

**R11 权限**：登录即可访问；管理员看全部用户（`scope=all`），普通用户只看自己的转发（`scope=self`），接口不得返回他人的速率。

**接口**：`POST /api/v1/flow-rate/current`（无参数）。轮询接口**不要**挂访问日志注解，避免每 2 秒刷一条日志。

**测试**：窗口换算/过期/按用户过滤/排序/零增量/清理；管理员与普通用户范围、空数据、Top 回退；真实上报 → 接口 → 角色隔离（含未登录 401、非法密钥忽略）。

### R12 管理员可见范围
- 实时速率对管理员返回 `scope=all`，**必须包含管理员自己创建的转发**，不能只统计被创建用户。
- 普通用户仍只看自己（`scope=self`），不得看到他人流量。

### R13 IPv6 双栈
- 面板后端与前端端口需同时监听 IPv4 与 IPv6（`0.0.0.0:PORT` + `[::]:PORT` 两条映射；nginx 需 `listen [::]:80;`）。
- 节点对接地址支持 `[IPv6]:端口` 形式，安装脚本校验与生成命令不得破坏方括号。
